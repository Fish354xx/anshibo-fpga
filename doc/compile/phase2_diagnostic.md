# 上板诊断版

上板反馈：首次显示应急素材，KEY2切换到欢迎素材后，KEY2/KEY3/KEY4均不再改变画面。
未确认根因。图片扫描顺序与文件名无关；控制模块单独仿真不能验证实际SD/SDRAM加载链路。

诊断版仅增加只读状态显示，经两级同步送往数码管。不改变加载逻辑。
下载文件：releases/phase2-emergency/anshibo_diagnostic.bit。
TD综合、布局布线及bit生成完成。时序尚未收敛，不能认为硬件验证已通过。

数码管按seg_data_0到seg_data_5依次表示：找到的图片数量、当前显示索引、加载目标索引、状态位、应急模式、BMP状态。
状态位从高位到低位是scan_done/bmp_ready/load_busy/emergency_mode，用十六进制显示。
例如普通空闲C、普通加载A、应急空闲D、应急加载B；实际板上左右顺序由数码管布线决定。
BMP状态1空闲、2扫描或读取头、3等待SDRAM写请求响应、4读取像素。

需收集上电显示后的数码管、按KEY2切到欢迎页后的数码管、再按KEY2等待10秒后的数码管照片。

## 实际验收记录（2026-10-02）

用户反馈400C01、411C01、422C01，KEY2可循环前三张，KEY4自动轮播，KEY3锁定第四张且屏蔽KEY2/KEY4，再次按下恢复。调整TF素材复制顺序后，用户确认功能和图片顺序均正确。
此前无响应现象未确定根因，诊断版上板后未复现。当前阶段验收通过，正式回退文件为anshibo_diagnostic.bit。
