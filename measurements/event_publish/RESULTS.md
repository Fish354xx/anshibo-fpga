# 应急事件事务发布：验证记录（2026-10-06）

## 本阶段范围

独立扩展已验收graded-alert。事件字段：16位编号、三级等级、区域1～16字符、正文1～64字符，使用607字形表及CRC16。元数据与字形先进入备用银行，合法完整事件才提交；视频侧同帧更新版本，回执在首个有效像素关联内部提交代次。本地同级或高等级优先。仅一个有效后台事件，不含视频、自动过期、语音或断电保持。

## 证据

1. event_packet：CRC参考123456789=29B1、规范包0001/1/AB/CDE=84BC；CRC失败、长度不足/过多、非法字形/范围、未准备好和缺应急图均拒绝；旧事件保持；完整相同重发不再应用；同编号变化拒绝；指定ID清除及取消待安装；最大16+64=80字；高字节字形606和末RAM单元；两组不同有效字形串CRC同为F5EF仍被识别为ID冲突。
2. event_display：逐像素验证区域字形；上传及等待主缓存时保留完整旧事件；新等级、区域和正文同帧安装；本地同级优先、隐藏低等级事件安装而不泄漏文字；本地解除后恢复已存后台内容；指定清除；解除后相同编号的新代次在首像素前保持PENDING，首像素后才APPLIED。
3. event_serial：实际100MHz/115200串口位时序驱动真实解析器和事务引擎，验证43字节ESTATUS、完整包、CRC错误、范围/长度错误、取消、指定清除及原等级控制。显示安装和TF加载在该协议测试中使用模型；不能当作真实HDMI显示证据。
4. uart_console：原17项协议、错误及忙状态回归通过。
5. remote_text：普通通知上传、显示缓存提交、字形及长度边界回归通过。此次长度63为测试设置后验证第64/65字，不等同完整64字上传。
6. event_protocol.ps1：Windows PowerShell实际离线测试通过，CRC独立参考、序列化、字符/空白/长度前置检查以及受理至输出状态流程；工具不需要Python运行。
