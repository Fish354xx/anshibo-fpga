2026-10-08。用户确认预加载固件运行正常。本阶段仅增加测试及记录，产品RTL和固件保持2009b5f版本。

## 视频帧门控测量

使用当前顶层中的原始emergency_audio_frame_gate及实际video_timing_data/color_bar，像素时钟25MHz。frame_gate.csv记录5种缓存提交相位；缓存标签的采用在测试平台注入。

- 缓存提交至可启动的帧首像素：1.414500、1.413540、14.214540、10.214540、2.214540 ms。
- 帧首有效像素判定与audio_enable上升在同一仿真时刻，差值0 ns。
- 该0 ns只指RTL门控事件，不代表实际HDMI音频采样、声音出声和显示器亮屏的差值。音频编码、传输及终端处理仍有延迟。
- 800×525×40 ns = 16.8 ms/帧。上述5次不是全相位穷举，也不是实测最大延迟。

## 预读调度模型测量

prefetch_model.csv使用实际sd_card_bmp控制代码，但强制卡初始化及目录就绪，模拟BMP完成和SDRAM写完成。时钟100MHz，图片0/应急图片源处理30周期，下一张1200周期，内存完成额外20周期；CLK_FREQ_HZ=1000缩短计时器，不用于轮播秒数性能测量。

| 事件 | 模型结果 |
|---|---:|
| 复位释放到首帧缓存提交 | 565 ns |
| 空闲时命令触发到应急缓存提交 | 555 ns |
| 预读100周期后命令触发到应急缓存提交 | 11795 ns |

这些数值只验证调度开销与排空等待，**不可作为真实启动或应急响应时间**。不包含TF初始化、FAT扫描、真实文件读取、SDRAM仲裁、按键消抖、分级长按或显示输出。触发是控制命令脉冲，不是串口字节或手指按键。
