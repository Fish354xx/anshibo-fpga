# 安视播：校园电子广告牌与完整应急事件发布

在现有校园信息发布工程中继续开发。日常图片切换轮播、TEXT普通通知、本地分级预警和声音规则保留。本阶段增加事件编号、预警等级、区域、正文、CRC校验及发布回执。活动视频、联网服务、事件有效期、语音播报和断电保持尚未实现。

## 上板操作

BitWriter使用PROGRAM_SRAM，只添加firmware/anshibo_slide_transition.bit下载。本阶段默认滑出滑入，支持TRANSITION SLIDE / FADE / CUT及查询；进入和解除应急直接切屏，详见TRANSITIONS.md。当前为待上板验收版本。TF四张图保持原样。退出旧串口窗口，双击本目录tools/launch_uart.cmd，选择已有COM端口（此前COM3）。

输入PUBLISH，向导依次录入：

- 事件编号：可以直接回车使用建议编号；更新内容请使用新编号。
- 等级：1提醒、2警戒、3紧急。
- 区域：1～16字符，例如“教学楼”。
- 正文：1～64字符，例如“消防演练，请有序离开教室”。

工具提前检查字符及长度，然后计算CRC并传输一个完整事务，FPGA收到全部内容且校验通过后一次提交。支持607个字形，不支持的字会在发送前提示；不需要改代码来更换已支持字符组成的文字。

ESTATUS查询该后台事件状态。APPLIED表示FPGA已开始输出该事件对应的显示帧，不能证明显示器或扬声器的物理响应已经完成。BLOCKED BY LOCAL表示已保存，本地同级或更高等级优先，解除本地预警后会显示。PENDING表示等待缓存或显示边界。NONE表示没有有效后台事件。

输入CLEAR清除当前后台事件，或CLEAR 123清除指定十进制编号。清除只影响后台，本地预警独立。原ALERT命令仍用于固定模板；已接受事件尚待银行安装时旧等级命令返回EVENTBUSY，此时可用指定编号的CLEAR取消。

本地KEY3选择/确认、KEY2切换候选等级、长按KEY3约2秒直接三级，保持上一阶段操作。日常TEXT不会覆盖应急正文。

## 显示与规则

一级：日常播放继续，提醒条显示正文，另外显示区域，普通通知仍在底部滚动。二级：警戒页显示区域和最多四行正文，间歇提示音。三级：使用TF第四张应急底图、区域及动态应急滚动正文，持续交替报警。声音由等级决定，本版没有独立音量/音色事件字段。

后台同时只保留一个最新有效事件，本地另保存一个等级；同级优先本地。完整事件在帧边界安装，错误CRC、缺失或多余字符不修改已有有效事件。当前事件同编号同内容返回DUP，不重新触发；同编号不同内容返回ID错误。历史事件编号没有长期去重记录。

解除后重新使用编号会建立新的内部提交代次，显示回执不会沿用旧代次。业务状态易失，复位或断电清零。串口断开不自动解除已有事件。未设置自动过期，二三级需明确解除。

## 验收

发布一个二级事件，检查区域和正文；换新编号发布不同内容；CLEAR恢复日常；本地长按三级后发布后台一级，应提示被本地覆盖；解除本地后检查该后台消息出现。确认日常TEXT仍正常。通过后保存GitHub。
